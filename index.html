Lane Detection Paper Notes

Summaries and feature/assumption comparison of lane detection methods, classified into 5 categories: (1) Segmentation-based (2) Anchor/row-wise-based (3) Parametric/curve-based (4) Keypoint-based (5) Transformer-based.

Papers

[1] Spatial As Deep: Spatial CNN for Traffic Scene Understanding (SCNN)
AAAI 2018 Category: Segmentation-based
Paper link

Standard CNNs build receptive field only by stacking layers, so information between two spatially distant but related pixels (e.g. a lane occluded by a car in the middle) only mixes indirectly, many layers later, once receptive fields happen to overlap. This is a poor fit for lane markings, which have a long, thin, continuous shape but weak/occluded appearance cues. Prior fixes for propagating context within a layer (RNNs scanning rows/columns, MRF/CRF with dense pairwise connections) either only mix in one direction, or connect every pixel to every other pixel directly, which is computationally very expensive.

SCNN instead propagates information sequentially, one row (or column) at a time. Take the topmost row of the feature map, convolve it with a small kernel to produce a "message," and add that message onto the row directly below it. Convolve this now-updated row to produce the next message, add it to the row below that, and repeat all the way down. This single sweep is called the downward pass. The same mechanism is then repeated for three more sweeps: upward (bottom row to top), rightward (leftmost column to rightmost), and leftward, each one run one after another, so that by the end every pixel has received context propagated in from all four directions. This module is inserted after the last hidden layer of a VGG16/LargeFOV segmentation backbone, followed by a 1x1 conv mapping features to per-pixel class scores (background plus a fixed number of lane slots), bilinear upsampling to the original image resolution, and a softmax to produce the final per-pixel lane segmentation mask. This output is a dense pixel mask rather than clean lane curves, so post-processing (thresholding, sparse point sampling, and curve fitting) is still required afterward to convert the mask into continuous lane lines.

Assumptions:

  1. Lane markings have a long, continuous shape prior: context needed to reconstruct an occluded/faint segment lies along the lane's own extent (rows/columns), not scattered arbitrarily.
  2. Local, incremental propagation (row → next row, column → next column) is sufficient, instead of connecting every pixel to every other pixel directly (as in dense MRF/CRF).
  3. The predicted per-lane pixel mask is clean and separable enough that post-processing (thresholding, sparse sampling, curve fitting) can produce an accurate lane line, with no major noise, gaps, or overlap between adjacent masks.
  4. The order of the four directional passes (down, up, right, left) matters, since each pass updates the feature map before the next one runs on it. The paper only tests adding directions one at a time; it doesn't test other orderings.

[2] A Keypoint-based Global Association Network for Lane Detection
CVPR 2022 Category: Keypoint-based
Paper link

Anchor-based methods represent each lane as a fixed straight-line template (an anchor) placed at a preset position and angle, and the network only predicts small corrections to bend or shift that straight line into the actual lane shape. Since the starting shape is always a straight line, this struggles to fit lanes that curve a lot. Keypoint-based methods fixed this by representing lanes as sets of keypoints instead, which can trace any shape. But they group keypoints into a lane one at a time: each keypoint is linked only to its immediate neighbor. This makes post-processing slow, and if one association is wrong, the rest of that lane's points can go wrong too, since each point only looks at its neighbor and not the lane as a whole.

GANet addresses these limitations by proposing a method to identify keypoints that belong to the same lane, without walking neighbor-to-neighbor. Every keypoint regresses an offset, indicating how far and in which direction to move from that keypoint to reach its lane's starting point. Keypoints whose predicted starting point locations land close to each other are grouped as the same lane. The image goes through a CNN backbone, then a self-attention layer for global context, followed by an FPN that combines features across scales into one feature map. From this feature map, two branches run in parallel. One branch refines features locally through the Lane-aware Feature Aggregator (LFA) module: for each point, it regresses a few nearby points likely on the same lane, samples their features, and combines them into a richer feature, which then feeds a keypoint head that outputs a confidence map indicating where a keypoint is, and a compensation map that recovers the precise sub-pixel position lost from downsampling. The second branch takes the FPN feature map directly into an offset head, which predicts each keypoint's offset to its lane's starting point. At inference, keypoints are filtered from the confidence map, the keypoints whose predicted offset is near zero are taken as starting points, and every other keypoint is assigned to whichever starting point its offset points closest to, with all of this done in parallel. Each assigned keypoint's precise image-coordinate position is then recovered using its compensation map value, and the keypoints belonging to each lane are simply connected in order to form the final lane line.

Assumptions:

  1. Different lanes' starting points are sufficiently well-separated in space that nearest-neighbor grouping does not mis-assign keypoints across lanes.
  2. Assigned keypoints are dense and accurate, which when connected in order, gives a smooth lane line.
  3. A keypoint's feature vector (possibly with local information of nearby keypoints), carries rich information to regress an accurate offset to a starting point that may be far away.
